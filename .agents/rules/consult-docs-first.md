# Consultar documentación ante problemas inesperados

Antes de aplicar cualquier workaround o solución ad-hoc a un problema inesperado (error de build, comportamiento raro de una dependencia, warning de deprecación, etc.), **siempre consultar la documentación oficial** de la herramienta o librería involucrada.

## Cuándo aplica

- Errores o warnings no triviales durante `npm install`, `vite build`, `vitest run`, o cualquier CLI.
- Comportamiento de una API que no coincide con lo esperado.
- Deprecaciones o cambios de versión mayor.
- Problemas de compatibilidad entre dependencias.

## Cómo hacerlo

1. Identificar la herramienta/librería exacta que genera el problema.
2. Consultar su documentación oficial (docs, changelog, migration guide) antes de buscar soluciones en foros o aplicar intuición.
3. Si la documentación no resuelve el problema, registrar el hallazgo con la solución encontrada para referencia futura.
